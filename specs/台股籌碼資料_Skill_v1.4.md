## 1. Skill 名稱
台股籌碼資料

## 2. 目的
從 tw-inst-screener 網站的 API 抓取台股「法人同步買超」、「主力吸籌掃描」、「疑似出貨風險訊號」與「單檔籌碼價量」資料，整理成**固定格式的資料包**。

本 Skill **只負責抓資料與整理格式，不做分析、不下結論**。需要分析報告時，把資料包交給 `stock-4d-3d-trade-report`（偏多交易劇本）或 `stock-dist-risk-report`（出貨風險與持股防守）產出報告。

所有數字都必須來自本次 API 回應，不可自行估算、補值或憑記憶填寫。

---

## 3. 執行觸發
當使用者輸入：
- `法人同步買超`、`同步買超`、`外資投信都買的股票`
- `吸籌掃描`、`主力吸籌`、`今天吸籌清單`
- `出貨風險`、`疑似出貨`、`今天出貨風險清單`、`空方訊號`
- `抓 2330 籌碼資料`、`2330 資料包`
- 或其他 Skill（例如 `stock-4d-3d-trade-report`）需要台股的法人、籌碼、價量資料時

即執行本 Skill。

使用者直接要求「分析 2330」、「2330 交易劇本」、「2330 四維共振」時：先由本 Skill 產出資料包（任務 C），再交給 `stock-4d-3d-trade-report`（見第 8 節）。
要求「2330 出貨風險」、「2330 持股防守」、「2330 空方分析」時：一樣先產出資料包，再交給 `stock-dist-risk-report`。

## 4. 資料來源

### BASE 網址
`BASE = https://tw-stocks.happytoo.cc`

### 端點
全部是 `GET`，回傳 JSON，不需要登入（除非網站設定了 API_TOKEN，此時要帶 `Authorization: Bearer <token>`）。

| 用途 | 網址 |
|---|---|
| A. 法人同步買超清單 | `{BASE}/api/cobuy?days=10&streak=5&insts=foreign,dealer&market=TPEX&sort=foreign&limit=50` |
| B. 吸籌掃描清單 | `{BASE}/api/scan?stage=ACCUMULATION,WATCH&min_score=50&market=TPEX&limit=50` |
| C. 單檔資料 | `{BASE}/api/stock/{4 位數代號}` |
| D. 疑似出貨風險清單 | `{BASE}/api/dist?stage=DISTRIBUTION,CAUTION&min_score=55&min_coverage=0.85&market=TPEX&limit=50` |

### 資料更新時間
每個交易日台北時間 18:00、20:00、22:45 更新，資料是**收盤後**的日資料，沒有盤中即時價。輸出時必須寫明資料日期。
借券賣出約 22:30 才公布，所以 22:45 之前的出貨結果不含當天借券（`sbl_status` 為 `pending`）。

### 防快取（每次呼叫都要做）
抓網頁的工具可能會把**同一個網址**的結果存起來，下次直接回傳舊資料（例如每天同一時間執行的排程）。所以每次呼叫都在網址最後加上 `_=<現在時間>`，讓網址每次都不同：

`{BASE}/api/scan?stage=ACCUMULATION&limit=50&_=202610210745`、`{BASE}/api/stock/2330?_=202610210745`

API 會忽略 `_` 參數，不影響結果。

### 資料日期核對（每次都要做）
先算出「應有的資料日」（台北時間）：
- 平日 18:30 之後 → 今天
- 其他時間（平日 18:30 前、週末）→ 前一個平日

再和回應的資料日期比較（`/api/scan`、`/api/dist`、`/api/stock` 看 `scan_date`；`/api/cobuy` 看 `trading_days` 最後一天）：
- 相同 → 正常。
- 比應有的資料日舊 → 換一個新的 `_` 值**重抓一次**；還是一樣就照第 9 節情況 F 處理。前端與本 Skill 都沒有交易日曆，國定假日也會出現這種情況，所以只能提醒，不能斷定是錯誤。

**清單與明細要同一天**：同一次任務中，清單（`/api/scan`、`/api/dist`、`/api/cobuy`）與每一檔明細（`/api/stock`）的資料日期必須相同。不同時，以**較新**的日期為準，換新的 `_` 值重抓較舊的那一份；仍不一致就照情況 F 處理，**不可**把不同日期的清單與明細合在同一份資料包或報告裡。

## 5. 任務與呼叫方式

### 任務 A：法人同步買超清單 → `/api/cobuy`

| 使用者說法 | 參數 |
|---|---|
| 外資／投信／自營商 | `insts=foreign`／`trust`／`dealer` |
| 外資和投信都買 | `insts=foreign,trust` |
| 三大法人都買 | `insts=foreign,trust,dealer` |
| 沒指定法人 | 不帶 `insts`（預設外資＋自營商），並在輸出中註明採用預設值 |
| 最近 N 天累計買超 | `days=N`（最多 10） |
| 連續買超 K 天 | `streak=K`（最多 10） |
| 上市／上櫃 | `market=TWSE`／`market=TPEX` |
| 前 N 檔 | `limit=N` |
| 依投信買超排序 | `sort=trust` |

篩選定義：勾選的**每個**法人都要各自符合「最近 `days` 日買賣超加總 > 0」且「從最後一天往前連續買超至少 `streak` 天」。

### 任務 B：吸籌掃描清單 → `/api/scan`

| 使用者說法 | 參數 |
|---|---|
| 吸籌、主力吸籌 | `stage=ACCUMULATION` |
| 觀察名單 | `stage=WATCH` |
| 過熱、漲多 | `stage=OVERHEATED` |
| 分數 X 分以上 | `min_score=X` |

### 任務 C：單檔資料包 → `/api/stock/{代號}`
- 只給名稱（例如「台積電」）時，先確認代號；無法確定就請使用者提供 4 位數代號，不要猜。
- 只支援 4 位數普通股。ETF（例如 0050）、權證、債券不支援。

### 任務 D：疑似出貨風險清單 → `/api/dist`

| 使用者說法 | 參數 |
|---|---|
| 疑似出貨、出貨風險 | `stage=DISTRIBUTION` |
| 注意名單 | `stage=CAUTION` |
| 暫定（資料不足） | `stage=PROVISIONAL` |
| 已大跌 | `stage=COLLAPSED` |
| 分數 X 分以上 | `min_score=X` |
| 資料要完整 | `min_coverage=0.85` |

## 6. 欄位與單位（必讀）

### 換算規則（輸出前一律換算好，下游 Skill 不必再換算）
| API 欄位 | API 單位 | 輸出時 |
|---|---|---|
| `/api/cobuy` 的 `*_sum`、`*_daily` | 張 | 照寫，標「張」 |
| `series[].foreign_net`、`trust_net`、`dealer_net`、`inst_net` | **股** | ÷ 1000，四捨五入到整數，標「張」 |
| `series[].volume`、`levels.volume`、`vol_ma5`、`vol_ma5_prev`、`vol_ma20` | **股** | ÷ 1000，四捨五入到整數，標「張」 |
| `inst_net_5` | **股** | ÷ 1000，四捨五入到整數，標「張」 |
| `series[].margin_balance` | 張 | 照寫，標「張」 |
| `inst_net_20_pct`、`trust_net_20_pct` | % 股本（0.8 = 0.8%） | 照寫加 `%`，**不要再乘 100** |
| `ret_20`、`dist_ma60`、`range_20`、`margin_chg_20`、`holders_chg_4w_pct` | 小數（0.05 = 5%） | × 100，取 1 位小數，加 `%` |
| `foreign_ratio_chg_20`、`big400_chg_4w` | 百分點 | 照寫，標「個百分點」 |
| `big400_pct`、`big1000_pct`、`retail_pct` | % | 照寫加 `%`，取 2 位小數 |
| `levels.*`（close、ma5、high_20…） | 元 | 照寫，取 2 位小數 |
| `avg_value_20` | 元 | ÷ 1 億，取 2 位小數，標「億元」 |
| `drawdown_60` | 小數（−0.08 = −8%） | × 100，取 1 位小數，加 `%` |
| `sbl_chg_20_pct`、`sbl_ratio` | % 股本 | 照寫加 `%`，取 2 位小數，**不要再乘 100** |
| `short_margin_ratio` | %（18.4 = 18.4%） | 照寫加 `%`，取 1 位小數 |
| `distribution.coverage` | 0～1 | × 100，取整數，加 `%` |
| `below_ma20` | 布林 | `true` 寫「是」、`false` 寫「否」 |
| `bear_lights.chip`、`volume`、`ma`、`pattern` | `true`／`false`／`null` | `true` 寫「已轉弱」、`false` 寫「還沒轉弱」、`null` 寫「資料不足」（**`null` 不可寫成還沒轉弱**） |

### 缺值
欄位為 `null` 代表資料不足（停牌、新上市、不能融資、集保週數不夠）。**一律寫「資料不足」，不可寫 0，也不可推論。**

### 訊號標籤中文對照
`inst_steady_buy` 法人緩買、`trust_buying` 投信買超、`big_holder_rising` 大戶連增、`holders_declining` 股東人數 4 週減少超過 2%、`price_quiet` 價格未動、`box_compression` 箱型收斂、`volume_mild` 量能溫和、`margin_exit` 融資退場、`overheated` 過熱、`tdcc_warming_up` 集保資料累積中、`missing:<欄位>` 該欄位資料不足。

出貨訊號：`inst_steady_sell` 法人持續賣、`trust_selling` 投信賣超、`big_holder_falling` 大戶連減、`holders_rising` 股東人數 4 週增加超過 2%、`off_high` 高點回落、`below_ma20` 跌破月線、`dump_bar` 帶量長黑、`sbl_rising` 借券增加、`margin_rising` 融資增加、`collapsed` 已大幅下跌、`low_coverage` 資料覆蓋不足、`sbl_pending` 當天借券未公布、`sbl_warming_up` 借券資料累積中、`market_assumed` 市場別推定。

### 階段中文對照
`ACCUMULATION` 吸籌（≥ 70 分）、`WATCH` 觀察（55～69 分）、`OVERHEATED` 過熱（20 日漲幅 > 25% 或量比 > 2.5）、`NEUTRAL` 中性、`EXCLUDED` 排除（20 日平均成交值 < 2,000 萬元或資料不足）。

出貨：`DISTRIBUTION` 疑似出貨（≥ 70 分且覆蓋率 ≥ 85%）、`CAUTION` 注意（55～69 分且覆蓋率 ≥ 85%）、`PROVISIONAL` 暫定（≥ 55 分但覆蓋率不足，不可當成正式結果）、`COLLAPSED` 已大幅下跌（不適用高檔派發判斷，不代表風險解除）、`NEUTRAL` 中性、`EXCLUDED` 排除。

用語：出貨相關一律寫「疑似出貨風險訊號」，不寫「主力正在出貨」。


計算規則：
- 「當日 ÷ 前 5 日均量」與「漲跌 %」是本 Skill 唯一需要自己算的數字，取 2 位小數；其中任一值為 `null` 就寫「資料不足」。
- 其他數字一律直接取自 API（`features`、`levels`、`series`），只做第 6 節的單位換算。

---

## 8. 交給 `stock-4d-3d-trade-report`

使用者要求分析報告、交易劇本、四維共振或 3D 盲點時：

1. 執行任務 C，產出完整資料包。
2. 呼叫 `stock-4d-3d-trade-report`，並明確告知：
   > 以下資料包是本次報告的數據來源。報告中的籌碼、量能、均線、價格區間數字以資料包為準；資料日期為 YYYY/MM/DD 收盤。若需要盤中即時價，另外查詢並標明時間，但不得用其他來源覆蓋資料包中的收盤後數據。
3. 附上資料包全文。
4. 若資料包有「資料不足」欄位，一併提醒：該維度的判斷要註明資料不足，不可推論。

一次分析多檔時（例如吸籌清單前 3 檔），逐檔產生資料包並分別交給報告 Skill，不要合併成一份。

使用者要求出貨風險、持股防守或空方分析時，步驟相同，改交給 `stock-dist-risk-report`；說明文字同上，另外提醒：出貨評分為實驗性，只適合當 20 日左右的風險提示。

## 9. 例外處理

### 情況 A：API 無法連線
逾時、DNS 失敗、HTTP 5xx 時，輸出：
> 本次資料抓取未能完成：無法連線到台股籌碼資料服務（錯誤：……）。

**禁止**改用記憶或其他網站的數字產生資料包，也**不要**呼叫 `stock-4d-3d-trade-report`。

### 情況 B：資料尚未產生
`/api/scan` 回 `503 { "error": "scan_not_ready" }`、`/api/dist` 回 `503 { "error": "dist_not_ready" }`，或 `/api/cobuy` 回 `503 { "error": "data_not_ready" }`：
> 資料服務目前尚未產生今日資料（通常在交易日 18:00 後更新），請稍後再查詢。

### 情況 F：資料日期比應有的資料日舊，或清單與明細日期不一致
重抓一次仍然一樣時：
- **比應有的資料日舊**：照常產出資料包，但在最前面加一行：
  > ⚠ 資料日期 YYYY/MM/DD，比應有的 YYYY/MM/DD 舊：可能是休市日、資料尚未更新，或讀到快取。以下內容以 YYYY/MM/DD 收盤為準。
- **清單與明細日期不一致**：不產出合併的資料包，只輸出：
  > ⚠ 清單資料日期 YYYY/MM/DD，個股明細 YYYY/MM/DD，兩者不一致（可能讀到快取）。請稍後再試。

不可把舊資料當成今天的資料描述，也不可自行用其他來源補上缺的日期。

### 情況 C：查無個股
`/api/stock` 回 `404 { "error": "not_found" }`：
> 查無 XXXX 的資料。本服務只涵蓋上市櫃 4 位數普通股（不含 ETF、權證），也可能是代號有誤或已下市。

不要呼叫 `stock-4d-3d-trade-report`。

### 情況 D：參數錯誤
回 `400`，回應會帶 `allowed`（允許值）或 `hint`（格式說明）。依此修正參數後重試一次；仍失敗就向使用者說明。

### 情況 E：沒有符合的股票
`count` 為 0 時，只輸出：
> **目前沒有符合條件的股票**

並附上本次的篩選條件。**不可**自行放寬條件後當成原條件的結果。

## 10. 品質控制 Checklist

輸出前逐項確認：

- [ ] 所有數字都來自本次 API 回應？
- [ ] 每次呼叫都加了 `_=<現在時間>`？資料日期和應有的資料日核對過？清單與每一檔明細是同一天？不符時有依情況 F 處理？
- [ ] 有寫資料日期，並註明是收盤後日資料？
- [ ] 股 → 張都已 ÷ 1000？
- [ ] 小數欄位都已 × 100 換成 %？`% 股本` 欄位沒有再乘 100？
- [ ] 四維偏空燈號照抄 `bear_lights`，沒有自己重算？`null` 寫成「資料不足」？
- [ ] `null` 都寫成「資料不足」？
- [ ] `tdcc_warming_up` 時有提醒？
- [ ] 有寫出採用的篩選條件（含預設值）？
- [ ] 資料包只有數字，沒有燈號、判斷或建議？
- [ ] 出貨資料寫「疑似出貨風險訊號」？`distribution` 為 null 時寫「沒有出貨資料」而不是「沒有風險」？`sbl_pending` 有註明？
- [ ] 交給報告 Skill 時有附上資料日期與「以資料包為準」的說明？
- [ ] API 失敗時沒有用其他來源補資料？

## 11. 核心原則

> **只抓資料，不做分析。**

分析與交易劇本由 `stock-4d-3d-trade-report` 負責；本 Skill 的輸出要讓它不必再查一次、也不必再算一次。

> **資料只來自 API。**

API 沒給的就寫「資料不足」，不用記憶或其他網站補。

> **單位換算好再交出去。**

張與股、% 與小數、百分點與百分比，在本 Skill 就換算完成，避免下游誤讀。

> **收盤資料就說是收盤資料。**

資料包是收盤後日資料，不是盤中即時價，必須寫清楚日期。
