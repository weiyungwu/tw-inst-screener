# 台股籌碼資料（TW Chip Data）Skill v1.1

## 1. Skill 名稱
台股籌碼資料

## 2. 目的
從 tw-inst-screener 網站的 API 抓取台股「法人同步買超」、「主力吸籌掃描」與「單檔籌碼價量」資料，整理成**固定格式的資料包**。

本 Skill **只負責抓資料與整理格式，不做分析、不下結論**。需要分析報告時，把資料包交給 `stock-4d-3d-trade-report` Skill 產出報告。

所有數字都必須來自本次 API 回應，不可自行估算、補值或憑記憶填寫。

---

## 3. 執行觸發
當使用者輸入：
- `法人同步買超`、`同步買超`、`外資投信都買的股票`
- `吸籌掃描`、`主力吸籌`、`今天吸籌清單`
- `抓 2330 籌碼資料`、`2330 資料包`
- 或其他 Skill（例如 `stock-4d-3d-trade-report`）需要台股的法人、籌碼、價量資料時

即執行本 Skill。

使用者直接要求「分析 2330」、「2330 交易劇本」、「2330 四維共振」時：先由本 Skill 產出資料包（任務 C），再交給 `stock-4d-3d-trade-report`（見第 8 節）。

---

## 4. 資料來源

### BASE 網址
`BASE = https://tw-inst-screener.<子網域>.workers.dev`

> 安裝本 Skill 時，請把 `<子網域>` 換成實際的 Cloudflare Workers 子網域。

### 端點
全部是 `GET`，回傳 JSON，不需要登入（除非網站設定了 API_TOKEN，此時要帶 `Authorization: Bearer <token>`）。

| 用途 | 網址 |
|---|---|
| A. 法人同步買超清單 | `{BASE}/api/cobuy?days=10&streak=5&insts=foreign,dealer&market=TPEX&sort=foreign&limit=50` |
| B. 吸籌掃描清單 | `{BASE}/api/scan?stage=ACCUMULATION,WATCH&min_score=50&market=TPEX&limit=50` |
| C. 單檔資料 | `{BASE}/api/stock/{4 位數代號}` |

### 資料更新時間
每個交易日台北時間 18:00 與 20:00 更新，資料是**收盤後**的日資料，沒有盤中即時價。輸出時必須寫明資料日期。

---

## 5. 任務與呼叫方式

### 任務 A：法人同步買超清單 → `/api/cobuy`

| 使用者說法 | 參數 |
|---|---|
| 外資／投信／自營商 | `insts=foreign`／`trust`／`dealer` |
| 外資和投信都買 | `insts=foreign,trust` |
| 三大法人都買 | `insts=foreign,trust,dealer` |
| 沒指定法人 | 不帶 `insts`（預設外資＋自營商），並在輸出中註明採用預設值 |
| 最近 N 天累計買超 | `days=N`（最多 10） |
| 連續買超 K 天 | `streak=K`（最多 10） |
| 上市／上櫃 | `market=TWSE`／`market=TPEX` |
| 前 N 檔 | `limit=N` |
| 依投信買超排序 | `sort=trust` |

篩選定義：勾選的**每個**法人都要各自符合「最近 `days` 日買賣超加總 > 0」且「從最後一天往前連續買超至少 `streak` 天」。

### 任務 B：吸籌掃描清單 → `/api/scan`

| 使用者說法 | 參數 |
|---|---|
| 吸籌、主力吸籌 | `stage=ACCUMULATION` |
| 觀察名單 | `stage=WATCH` |
| 過熱、漲多 | `stage=OVERHEATED` |
| 分數 X 分以上 | `min_score=X` |

### 任務 C：單檔資料包 → `/api/stock/{代號}`
- 只給名稱（例如「台積電」）時，先確認代號；無法確定就請使用者提供 4 位數代號，不要猜。
- 只支援 4 位數普通股。ETF（例如 0050）、權證、債券不支援。

## 6. 欄位與單位（必讀）

### 換算規則（輸出前一律換算好，下游 Skill 不必再換算）
| API 欄位 | API 單位 | 輸出時 |
|---|---|---|
| `/api/cobuy` 的 `*_sum`、`*_daily` | 張 | 照寫，標「張」 |
| `series[].foreign_net`、`trust_net`、`dealer_net`、`inst_net` | **股** | ÷ 1000，四捨五入到整數，標「張」 |
| `series[].volume`、`levels.volume`、`vol_ma5`、`vol_ma20` | **股** | ÷ 1000，四捨五入到整數，標「張」 |
| `series[].margin_balance` | 張 | 照寫，標「張」 |
| `inst_net_20_pct`、`trust_net_20_pct` | % 股本（0.8 = 0.8%） | 照寫加 `%`，**不要再乘 100** |
| `ret_20`、`dist_ma60`、`range_20`、`margin_chg_20`、`holders_chg_4w_pct` | 小數（0.05 = 5%） | × 100，取 1 位小數，加 `%` |
| `foreign_ratio_chg_20`、`big400_chg_4w` | 百分點 | 照寫，標「個百分點」 |
| `big400_pct`、`big1000_pct`、`retail_pct` | % | 照寫加 `%`，取 2 位小數 |
| `levels.*`（close、ma5、high_20…） | 元 | 照寫，取 2 位小數 |
| `avg_value_20` | 元 | ÷ 1 億，取 2 位小數，標「億元」 |

### 缺值
欄位為 `null` 代表資料不足（停牌、新上市、不能融資、集保週數不夠）。**一律寫「資料不足」，不可寫 0，也不可推論。**

### 訊號標籤中文對照
`inst_steady_buy` 法人緩買、`trust_buying` 投信買超、`big_holder_rising` 大戶連增、`holders_declining` 股東減少、`price_quiet` 價格未動、`box_compression` 箱型收斂、`volume_mild` 量能溫和、`margin_exit` 融資退場、`overheated` 過熱、`tdcc_warming_up` 集保資料累積中、`missing:<欄位>` 該欄位資料不足。

### 階段中文對照
`ACCUMULATION` 吸籌（≥ 60 分）、`WATCH` 觀察（45～59 分）、`OVERHEATED` 過熱（20 日漲幅 > 25% 或量比 > 2.5）、`NEUTRAL` 中性、`EXCLUDED` 排除（20 日平均成交值 < 2,000 萬元或資料不足）。

## 7. 輸出格式

### 任務 A：法人同步買超清單

# 法人同步買超資料

- **資料日期**：YYYY/MM/DD（期間 YYYY/MM/DD ～ YYYY/MM/DD，共 N 個交易日）
- **篩選條件**：[法人] 各自 N 日累計買超 > 0 且連續買超 ≥ K 天；市場：[全部／上市／上櫃]（[若有預設值，註明「採用預設」]）
- **符合檔數**：共 X 檔，以下列出前 Y 檔
- **資料來源**：tw-inst-screener `/api/cobuy`

| 代號 | 名稱 | 市場 | 外資累計(張) | 外資連買(天) | 投信累計(張) | 投信連買(天) | 自營累計(張) | 自營連買(天) |
|---|---|---|---|---|---|---|---|---|

（只列使用者勾選的法人欄位。）

### 任務 B：吸籌掃描清單

# 主力吸籌掃描資料

- **掃描日**：YYYY/MM/DD
- **集保資料**：最新 YYYY/MM/DD，累積 N 週（[若 `quality` 為 `tdcc_warming_up`：⚠ 集保資料累積不足，籌碼集中分數僅供參考]）
- **篩選條件**：[階段]，最低 X 分，市場 [全部／上市／上櫃]
- **符合檔數**：共 X 檔，以下列出前 Y 檔
- **資料來源**：tw-inst-screener `/api/scan`

| 代號 | 名稱 | 階段 | 分數 | 法人/30 | 集中/30 | 價格/20 | 量能/10 | 融資/10 | 訊號 |
|---|---|---|---|---|---|---|---|---|---|

### 任務 C：單檔資料包（交給 `stock-4d-3d-trade-report` 的格式）

資料包依 4 維共振的四個維度分組，**只寫數字，不寫燈號、不寫判斷**。

```
# 【代號 名稱】台股籌碼資料包

## 基本資訊
- 資料日期：YYYY/MM/DD（收盤後日資料，非盤中即時）
- 市場：上市／上櫃
- 收盤價：NT$ X（前一交易日收盤 NT$ X，漲跌 X%）
- 吸籌掃描：階段 [中文]，總分 X / 100（法人 X/30、集中 X/30、價格 X/20、量能 X/10、融資 X/10）
- 訊號：[中文訊號清單；沒有寫「無」]
- 資料品質：[若 tdcc_warming_up：集保資料累積 N 週，不足 4 週]；資料不足欄位：[missing 清單；沒有寫「無」]
- 資料來源：tw-inst-screener /api/stock/代號

## 維度 1：籌碼
- 法人 20 日：外資＋投信淨買超 X% 股本；20 天中 X 天淨買超；投信 X% 股本；自營商 X% 股本
- 外資持股比率 20 日變化：X 個百分點
- 近 5 日三大法人（張）：
  | 日期 | 外資 | 投信 | 自營商 |
  |---|---|---|---|
  | （由 series 最後 5 筆換算） |
- 集保（最新 YYYY/MM/DD）：400 張以上大戶 X%（連續週增 X 週，4 週變化 X 個百分點）；千張大戶 X%；50 張以下散戶 X%；股東 X 人（4 週變化 X%）
- 融資：最新餘額 X 張；20 日變化 X%

## 維度 2：量能
- 當日成交量：X 張
- 5 日均量：X 張（當日 ÷ 5 日均量 = X 倍）
- 20 日均量：X 張
- 量比（20 日均量 ÷ 60 日均量）：X 倍
- 20 日平均成交值：X 億元

## 維度 3：均線
- 收盤 NT$ X
- MA5 NT$ X、MA10 NT$ X、MA20 NT$ X、MA60 NT$ X
- 季線乖離：X%

## 維度 4：型態（價格區間）
- 20 日最高 NT$ X、最低 NT$ X（20 日振幅 X%）
- 60 日最高 NT$ X、最低 NT$ X
- 20 日漲幅：X%
- 近 20 日日 K（元、張）：
  | 日期 | 開 | 高 | 低 | 收 | 量 |
  |---|---|---|---|---|---|
  | （series 20 筆，由舊到新） |
```

計算規則：
- 「當日 ÷ 5 日均量」與「漲跌 %」是本 Skill 唯一需要自己算的數字，取 2 位小數；其中任一值為 `null` 就寫「資料不足」。
- 其他數字一律直接取自 API（`features`、`levels`、`series`），只做第 6 節的單位換算。

## 8. 交給 `stock-4d-3d-trade-report`

使用者要求分析報告、交易劇本、四維共振或 3D 盲點時：

1. 執行任務 C，產出完整資料包。
2. 呼叫 `stock-4d-3d-trade-report`，並明確告知：
   > 以下資料包是本次報告的數據來源。報告中的籌碼、量能、均線、價格區間數字以資料包為準；資料日期為 YYYY/MM/DD 收盤。若需要盤中即時價，另外查詢並標明時間，但不得用其他來源覆蓋資料包中的收盤後數據。
3. 附上資料包全文。
4. 若資料包有「資料不足」欄位，一併提醒：該維度的判斷要註明資料不足，不可推論。

一次分析多檔時（例如吸籌清單前 3 檔），逐檔產生資料包並分別交給報告 Skill，不要合併成一份。

## 9. 例外處理

### 情況 A：API 無法連線
逾時、DNS 失敗、HTTP 5xx 時，輸出：
> 本次資料抓取未能完成：無法連線到台股籌碼資料服務（錯誤：……）。

**禁止**改用記憶或其他網站的數字產生資料包，也**不要**呼叫 `stock-4d-3d-trade-report`。

### 情況 B：資料尚未產生
`/api/scan` 回 `503 { "error": "scan_not_ready" }`，或 `/api/cobuy` 回 `503 { "error": "data_not_ready" }`：
> 資料服務目前尚未產生今日資料（通常在交易日 18:00 後更新），請稍後再查詢。

### 情況 C：查無個股
`/api/stock` 回 `404 { "error": "not_found" }`：
> 查無 XXXX 的資料。本服務只涵蓋上市櫃 4 位數普通股（不含 ETF、權證），也可能是代號有誤或已下市。

不要呼叫 `stock-4d-3d-trade-report`。

### 情況 D：參數錯誤
回 `400`，回應會帶 `allowed`（允許值）或 `hint`（格式說明）。依此修正參數後重試一次；仍失敗就向使用者說明。

### 情況 E：沒有符合的股票
`count` 為 0 時，只輸出：
> **目前沒有符合條件的股票**

並附上本次的篩選條件。**不可**自行放寬條件後當成原條件的結果。

## 10. 品質控制 Checklist

輸出前逐項確認：

- [ ] 所有數字都來自本次 API 回應？
- [ ] 有寫資料日期，並註明是收盤後日資料？
- [ ] 股 → 張都已 ÷ 1000？
- [ ] 小數欄位都已 × 100 換成 %？`% 股本` 欄位沒有再乘 100？
- [ ] `null` 都寫成「資料不足」？
- [ ] `tdcc_warming_up` 時有提醒？
- [ ] 有寫出採用的篩選條件（含預設值）？
- [ ] 資料包只有數字，沒有燈號、判斷或建議？
- [ ] 交給報告 Skill 時有附上資料日期與「以資料包為準」的說明？
- [ ] API 失敗時沒有用其他來源補資料？

## 11. 核心原則

> **只抓資料，不做分析。**

分析與交易劇本由 `stock-4d-3d-trade-report` 負責；本 Skill 的輸出要讓它不必再查一次、也不必再算一次。

> **資料只來自 API。**

API 沒給的就寫「資料不足」，不用記憶或其他網站補。

> **單位換算好再交出去。**

張與股、% 與小數、百分點與百分比，在本 Skill 就換算完成，避免下游誤讀。

> **收盤資料就說是收盤資料。**

資料包是收盤後日資料，不是盤中即時價，必須寫清楚日期。
