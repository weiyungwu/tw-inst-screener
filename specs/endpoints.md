## 共通解析規則

- 數字字串有千分位逗號，一律先去掉逗號再轉型。
- **缺值寫法**：TWSE 用 `--`，TPEX 價格用 `----`、漲跌用 `---`。這些都要存 `NULL`，**不可以存 0**。成交股數為 `"0"` 時是真的 0，照實存。
- 欄位名稱常帶前後空白或 `<br>`（TPEX），比對前要 trim。
- 代號欄可能有尾端空白（例如 TWSE 名稱 `"台積電          "`），要 trim。
- 主表要用 title 或欄位名稱定位，不要寫死 `tables[n]`。MI_INDEX 的表格順序在不同日期可能會變。

## tdcc 歷史查詢頁（P3 實作，用於回補）

集保官網的查詢頁 `https://www.tdcc.com.tw/portal/zh/smWeb/qryStock` 有約一年的歷史資料（官方說明「資料保存期間為一年」）。和規格 §3.1「集保歷史無法免費回補」不同。

- 流程：先 GET 頁面，取得 `JSESSIONID` cookie、`SYNCHRONIZER_TOKEN`，以及 `<select id="scaDate">` 的週別清單（新到舊，例如 `20261002, 20260924, 20260918`）。再 POST `method=submit&firDate=<最新週>&scaDate=YYYYMMDD&sqlMethod=StockNo&stockNo=XXXX&stockName=&SYNCHRONIZER_TOKEN=…&SYNCHRONIZER_URI=/portal/zh/smWeb/qryStock`。
- **每次回應都會換新的 token**，下一次 POST 要用新的 token。回應裡沒有 token 就代表 session 失效，要重新 GET。
- 週別不一定是週五：2026-09-25（中秋）休市，所以那一週是 `20260924`。
- 結果表欄位：`序, 持股/單位數分級, 人數, 股數/單位數, 占集保庫存數比例 (%)`，共 17 列。資料日期以民國年顯示：`資料日期：115年09月24日`，要和要求的週別比對。
- 查無資料時，表格內只有一列「查無此資料」，資料日期是空的。
- **第 16 級和 CSV 不同**：股數和比例帶正確的負號（`-1,000`、`-0.00`），人數是空白（存 0）。CSV 的人數則有值（例如 2330 是 2），但不計入合計。
- 限制：一次請求只能查一檔一週，所以只回補 `stocks` 表裡的上市櫃普通股（約 1,972 檔）。CSV 的 2,958 檔包含興櫃，不在其他資料源內。
- 用法：`node scripts/backfill.mjs --tdcc-weeks N`，回補最新週之前的 N 週。每檔查完立即寫入，可以中斷後續跑。
- `fetched_at` 填實際抓取時間。回補的歷史週 fetched_at 會晚於 data_date，回測時依 point-in-time 規則，這些週只有在抓取日之後才算可用。這比較保守，但不會偷看未來。

### 第 16 級的儲存規則

兩個來源都存**真實帶號值** = 第 17 級股數 − Σ(第 1～15 級股數)，和官網顯示一致（2330 在 2026-10-02 是 −7,900）。比例的正負號跟著股數。驗證規則：|來源的第 16 級| 必須等於這個差額，而且 Σ人數(1～15) = 第 17 級人數。

### 勾稽（自我驗證欄位位置）

- 借券：前日餘額 + 當日賣出 − 當日還券 + 當日調整 = 當日餘額（2330：12,051,514 + 785,000 − 39,000 + 0 = 12,797,514 ✓）
- 融券（股）：前日 + 賣出 − 買進 − 現券 = 今日（2330：23,000 + 2,000 − 17,000 − 0 = 8,000 ✓，等於 MI_MARGN 的 8 張）
- **全列檢查（2026-10-15 完整回應）**：TWSE 1,304 列、TPEX 932 列，兩條公式全部成立，餘額沒有負值，代號沒有重複，沒有例外。
- ⚠️ 當天兩市場所有列的「當日調整」都是 0，所以調整項的**正負號還沒被實際資料驗證過**。之後遇到調整不為 0 的列，若勾稽不符，要先檢查是不是正負號的問題，不要直接放寬驗證。
